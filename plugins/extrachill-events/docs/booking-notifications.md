# Booking Notifications

Booking lifecycle events use Extra Chill Users `ec_users_notify_with_receipts()` directly. Every delivery payload includes the `extrachill-events-booking` producer and a stable source-activity idempotency key, so retries converge on the Users table's per-recipient delivery receipt. Events does not own a parallel notification table.

Each event definition owns an explicit recipient policy. New inquiries notify active venue owners. Assignment changes, hold expiry, and event handoff failures notify active owners plus the current event assignee. Information received notifies the active assignee. Revoked, invited, cross-venue, missing, and unrelated active members are excluded while the exact venue membership range and booking are locked.

Outbox recovery remains append-only and bounded. Each request attempt owns a deterministic advisory lock, then re-reads terminal and persisted due state before selecting recipients or calling Users. Dependency errors, delivery failures, attempts, exponential due times, and terminal suppression are persisted monotonically before that lock is released. A second worker therefore sees either a terminal result or a durable not-yet-due attempt, never an unrecorded failure window. Due-only selection lets newer work advance while older failures wait. Five unsuccessful attempts produce a terminal `delivery_poisoned` suppression. Overlapping jobs cannot deliver or append duplicate attempts, and poison rows cannot starve newer requests. Successful and exact replay receipts remain independently idempotent from correspondence delivery.
