# Booking correspondence

Venue booking configuration version 2 contains a versioned `correspondence` section with a booking address, fixed variable schema, three plain-text templates, and reminder policies. Persisted version 1 documents and version 1 update clients normalize into version 2. Updates use the existing venue-scoped revision lock and atomic audit record.

`extrachill/preview-booking-correspondence-template` requires venue authorization and an expected template version. The send path uses the same renderer, derives booking and venue variables server-side, and snapshots the rendered subject and body in the durable intent. Enabled reminder policies own the delay and expected statuses; dispatch suppresses a pending reminder if its template or policy version changes. Rendering is a single non-recursive replacement pass over allowlisted `{{variable}}` tokens. Unknown variables, subject newlines, unsupported template keys, stale versions, and invalid reminder statuses are rejected.

End-to-end email threading and inbound attachment ingestion remain blocked by [Data Machine #2992](https://github.com/Extra-Chill/data-machine/issues/2992). Events must not invent a second transport or mailbox. The blocker must first provide queued-send threading headers, durable outbound Message-ID receipts, opaque inbound provider references, private attachment handoffs, and provider-authenticated sender evidence suitable for SPF/DKIM/DMARC-equivalent trust decisions. Extra-Chill/extrachill-events#313 stays open until that contract is available and the remaining ingestion, matching, human-reply suppression, and reconciliation work is complete.
